# lhg-ug-metrics：增长指标口径

> 目标：让团队说同一个"增长"——北极星指标 1 个、口径定义人人可查、实验前后用同一把尺子。
> 核心纪律：**指标无口径 = 没指标；复盘换口径 = 换实验。**

## 1. 何时使用

- 团队各说各话（"增长了"指的都不是一件事）→ 定北极星 + 写口径文档
- 实验卡的成功指标写不出来/写出来没法算 → 回来查本 skill
- 复盘时发现前后数据对不上 → 检查口径是否一致
- **不适用**：纯粹的数据埋点技术实现（埋点代码怎么写）→ 那是工程问题，不在本 skill 范围

## 2. 输入与输出

### 输入
- 产品形态与商业模式（决定北极星候选）
- 现有的数据口径（统计后台、表格，截图/描述都行）

### 输出
- 北极星指标 1 个（一句话定义 + 为什么是它）
- 口径定义文档（`docs/metrics-definitions.md`）：每个指标含定义、分母、统计周期、数据来源
- 输入/输出指标分层表

## 3. 分步方法论

### 第 1 步：定北极星指标（只 1 个）
北极星 = 最能代表"产品为用户创造价值"的 1 个指标。选题三问：
1. 用户在你产品里得到价值的瞬间是什么？（如：发布 1 篇笔记、完成 1 单、学完 1 节课）
2. 这个瞬间可数吗？→ 可数才行，"用户很开心"不可数
3. 它涨了，收入/留存会跟着涨吗？→ 不跟涨的就是虚荣指标

常见产品形态的北极星参考（**参考，不是标准答案**）：
- 内容社区：周活跃创作者数（不是 DAU，创作者才是价值源头）
- 电商：周下单用户数（不是 GMV，GMV 会被客单价注水）
- 工具：周核心功能使用次数（不是下载量）
- SaaS：付费工作区数（不是注册数）
- 教育：周完课人次（不是报名数）

**北极星定了就别轻易换**：换一次，历史对比全废。实在要换，新旧并行跑 1 个月。

### 第 2 步：分层——输入指标 vs 输出指标
- **输出指标**（结果）：北极星、各环节转化率——它们涨了是好事，但你不能直接"做"它们
- **输入指标**（抓手）：你能直接动手改的——新手引导完成率、推送打开率、邀请发送量

实验的成功指标优先选**输入指标**（动作直接影响它，归因干净）；北极星用来看大盘（别指望 1 个实验撬动它）。

### 第 3 步：写口径定义文档
每个指标 4 要素，缺一不可：
1. **定义**：分子/分母是什么（如"7 日留存 = 注册后第 7 天仍活跃的用户 / 当日新增注册用户"）
2. **统计周期**：按天/周/月（"留存"不说第几日就是耍流氓）
3. **数据来源**：哪个后台/哪张表（"后台看的"不算来源）
4. **排除项**：测试账号、内部员工、刷量渠道是否排除

模板：
```markdown
## 指标：7 日留存
- 定义：注册后第 7 天有 1 次活跃的用户 / 当日新增注册用户
- 周期：按注册日 cohort，天粒度
- 来源：xx 统计后台 → 留存分析
- 排除：内部测试账号（uid < 1000）
```

### 第 4 步：AARRR 各环节常用指标速查
| 环节 | 常用指标 | 口径提醒 |
|---|---|---|
| 获客 | 新增注册/下载、CAC（获客成本） | 分渠道看，混在一起没意义 |
| 激活 | 激活率（完成啊哈时刻/新增） | "啊哈时刻"必须先定义 |
| 留存 | 次日/7 日/30 日留存 | 按 cohort 算，不用大盘平均糊弄 |
| 变现 | 付费转化率、ARPU、LTV | LTV 要说明测算方法 |
| 推荐 | 分享率、K 系数 | K=人均邀请数×邀请转化率 |

### 第 5 步：口径一致性检查
- 实验卡的成功指标 → 必须能在口径文档里找到，或现场补一条定义
- 复盘用的数字 → 必须与实验卡同一口径；口径变了，复盘结论作废重算
- 定时（每月）抽查：随机抽 1 个指标，按文档定义重算一遍，对不上就修文档或修数据

## 4. 反模式

- ❌ 指标 10 个"都很重要"——都很重要 = 都不重要，先保北极星
- ❌ 口径只存在某人口头上——人一走，历史数据全成天书
- ❌ 用大盘平均代替 cohort（"我们留存 40%"——哪一批的 40%？）
- ❌ 虚荣指标当北极星（粉丝数、阅读量、下载量）——涨了也不产生价值
- ❌ 实验成功指标选北极星——1 个实验撬不动北极星，选了等于注定"无法判断"
- ❌ 口径文档写完就锁进抽屉——新人口径对不上，文档要随手可查（如放 docs/ 目录）

## 6. 口径文档完整示例

```markdown
# 指标口径定义（版本 2026-10-11，负责人：小李）
## 北极星：周活跃创作者数
- 定义：自然周内发布 ≥1 篇内容的用户数
- 周期：自然周（周一 00:00 至周日 24:00）
- 来源：数据后台 → 内容分析 → 创作者周报
- 排除：内部测试账号（uid < 1000）、单周发布 >50 篇的疑似刷量账号
- 为什么是它：创作者产出内容 → 内容带来读者 → 读者转化创作者，飞轮起点

## 指标：付费转化率
- 定义：自然月内付费 ≥1 次的用户 / 当月活跃用户
- 周期：自然月
- 来源：支付后台 → 订单表（去重 uid）
- 排除：退款订单、0 元体验单
```

### 口径变更流程
1. 谁都可以提变更，但必须写"变更原因 + 影响范围（哪些历史结论要重算）"
2. 指标负责人（1 个人）审批
3. 变更后版本号 +1，旧口径保留 3 个月备查
4. **实验进行中不许变口径**——要变就等实验结束，否则本轮结论作废

### 常见问题
- **Q：北极星选错了怎么办？** A：先并行跑新旧两个指标 1 个月，确认新指标更准再切换；切换后历史结论标注"旧口径"。
- **Q：小团队没数据后台，口径文档怎么做？** A：先用表格手工记（日期/分子/分母/来源），口径文档照样写——"来源：手工台账"也是来源。
- **Q：指标太多了看不过来？** A：每天只看北极星 + 1 个输入指标；其他的周报再看。看不过来的指标等于没有指标。

## 7. 自检与反馈

交付前自问：
1. 北极星是否只有 1 个且有"为什么是它"的一句话理由？
2. 每个指标 4 要素是否齐了？
3. 实验卡的成功指标能在口径文档里找到吗？

标准冒烟用例：审计脚本 `UG-MET-002/003` 校验实验卡指标口径（见仓库根 `smoke_test.py`）。
