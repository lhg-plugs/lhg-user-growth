# /lhg-user-growth:audit —— 实验清单体检

用户输入在 `$ARGUMENTS` 中：`[实验卡目录或文件] [--fix]`。缺省扫描当前目录下的 markdown 实验卡。

## 流程

### 1. 跑脚本
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/experiment_audit.py --target <目录或文件> --format text
```
记下 blocker / warning 的数量与明细（含文件、行号、规则说明）。

### 2. 分级与修复
- blocker（缺假设/缺成功指标/缺动作/复盘缺结论）：逐条补。`--fix` 缺省不自动补内容（内容要人写），只输出"待补充清单"让用户/助手逐项填；填完复跑脚本确认消失。
- warning（缺周期/缺负责人/虚荣指标/指标口径不一致）：补上或写豁免理由。
- 修不掉的 → 列入"需人工处理"，不许为清零改规则。

### 3. 人工评审（脚本覆盖不到的）
- 假设的"因为"部分是否真的是因果，还是套话？
- 成功指标的基线数字来源是否可信（实测/估算/拍脑袋，标清）？
- 实验之间是否互相干扰（同期跑 3 个改同一页面的实验）？
- 复盘结论的归因是否站得住（有没有同期其他动作在影响）？

### 4. 输出报告
按模板输出，存为 `docs/growth-audit-YYYYMMDD.md`：
```markdown
# 增长实验体检报告（日期）
## 结论：通过 / 不通过
## blocker（n）：已补 n，剩余 n
## warning（n）：已处理 n，豁免 n（理由）
## 人工评审结论
## 需人工处理
```

## 硬规则
- 有 blocker 就说"通过" → 不许。
- 为清零改脚本规则或阈值 → 作弊，不许。
- 实验卡的内容缺项（如缺假设）不许用模板话术自动填充：缺的就是缺的，让人补。
